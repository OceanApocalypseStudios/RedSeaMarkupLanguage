* RSML supports both .NET 10.0 and .NET Standard 2.0,
  so you can have both performance and backwards-compatiblity
  depending on the context and your needs.

  However, this brings up some issues: not everything implemented
  in .NET 10.0 is available for .NET Standard 2.0.

  To solve this, I came up with 2 forms of making code framework
  specific.

> THE CODE IS A TYPE ON ITS OWN AND THAT SHOULD BE ONLY AVAILABLE
  FOR A GIVEN FRAMEWORK
  Name the file as usual, but inside of it wrap all the content
  like this:

  - For a .NET 10.0 only type:
    --------------------------
    #if NET10_0_OR_GREATER
    ...
    #endif

  - For a .NET Standard 2.0 only type:
    ----------------------------------
    #if NETSTANDARD2_0
    ...
    #endif

> THE CODE IS PART OF A TYPE AND SHOULD BE RESOLVED BASED ON THE
  FRAMEWORK
  For a part of a type stored in MyFile.cs, name the framework
  dependent file (the one that will have the framework specific
  part of the type) like this:

  - For a .NET 10.0 only type: MyFile.DotNet10.cs
  - For a .NET Standard 2.0 only type: MyFile.DotNetStd20.cs
  
  ! No wrapping and no #ifs are necessary in this case, because
    the project file has rules to deal with these names.
